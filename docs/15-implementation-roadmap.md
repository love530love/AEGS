# AEGS 开发路线图

本路线图将“头脑风暴”转化为有依赖、可验收、可回滚的实现顺序。任何阶段的候选能力都必须经过 Charter、Proposal、Experiment（如适用）和人类决定，不能因列入路线图而自动启用。

## 已完成：原型基线

- `.aegs/` 治理包、JSONL 哈希账本、提案/决定、结构化反馈。
- 本机人类控制台、只读架构发现、JSON/Markdown 交接包。
- `takeover` 新鲜度门控：绑定非治理代码指纹、账本头和架构快照。
- v0.2 领域模型设计基线。

## M1：可信决策与可验证接管（当前）

| 工作项 | 结果 | 验收 |
|---|---|---|
| 结构化 Proposal | 范围、替代方案、影响、反方证据、验收标准、有效期 | YELLOW/RED 缺少任一字段不可批准 |
| 决定理由 | 每项高风险决定有可追溯原因 | 缺证据、回滚或理由不可批准 |
| 交接绑定 | Handoff 绑定代码、账本、快照 | 任一改变返回 STALE/HOLD |
| 过期/脏状态策略 | 清楚区分治理产物提交与业务代码变动 | 仅 `.aegs` 变化不误报；业务代码变化阻断接管 |

## M2：事件一致性与项目接入

- SQLite 事务事件存储或等价单写入者机制；并发写入、崩溃恢复和重放测试。
- State/Proposal/Directive 改为账本派生视图，直接编辑检测为 HOLD。
- 架构快照 Diff、人工确认未知项、`aegs doctor`。
- 三个参考适配器：Python、Node/Web、文档/研究项目。

验收：陌生 Agent 无历史聊天记录，10 分钟内运行接管检查、识别 STOP 条件，并完成一个低风险变更的完整证据链。

## M3：实验、评估与回滚

- Shadow Lab Runner、冻结基线/任务集/环境 manifest。
- Outcome 与 Evaluation 分离、回归/迁移/成本/安全评估矩阵。
- 版本化发布工件和可执行 rollback；`HOLD` 接入全部执行适配器。

## M4：受控能力演进

- Skill/Capability Registry 和淘汰记录。
- Capability Gap Detection、跨项目受限经验复用。
- 技术雷达：官方来源/许可证/供应链审查后，仅创建候选提案。
- 按风险动态召唤 Expert、Critic、Red Team 与 Stakeholder 角色。

## 明确延后

基础模型权重自改、无审批生产自治、自动权限扩大、自动安装外部能力、固定大规模 Agent 群、代币/区块链机制。
