# AEGS v0.2 产品需求

## 产品定位

AEGS 是跨项目的 AI 治理控制面。它为已有代码、数据、文档或研究项目提供可移植的项目治理包，使不同模型、Agent 或人类接手者能够在证据、权限和版本约束下继续工作。

## 主要使用者

| 角色 | 核心任务 |
|---|---|
| 项目所有者 | 设定宪章、审批高风险变更、随时冻结或回滚 |
| 开发者/维护者 | 理解状态、复现变更、审查代码和测试 |
| 执行 Agent | 读取受限上下文，产生 Trace、提案和可验证产物 |
| 审计/安全角色 | 核验证据、权限、来源、回归和异常 |
| 利益相关方代表 | 提供可追溯需求、可用性和成本反馈 |

## P0 功能需求

1. 每个接入项目拥有版本化 `.aegs/` 治理包：Charter、状态、交接、提案、实验、评估、决定与证据索引。
2. 新 Agent 进入时必须运行接管检查：验证 Git/环境、读取 Charter、核验状态和账本、报告未知项；未通过时只允许只读诊断。
3. 每项变更以不可变 `proposal_id` 创建；必须记录范围、风险、评估、批准和回滚指针。
4. 人类可在控制台审批、拒绝、暂缓、要求证据、冻结和回滚；每个动作生成 HumanDirective 和审计事件。
5. 运行时提供 Trace、证据链、版本时间线和可重放 manifest。
6. 能力发现只能创建候选提案；下载、启用工具、扩大访问或写入生产均须经过对应政策门控。

## 非功能需求与验收标准

| 目标 | v0.2 验收 |
|---|---|
| 接续性 | 新 Agent 不读取旧聊天记录，仍能在 10 分钟内输出已验证事实、未知项、风险与下一安全动作 |
| 可追溯 | 任一生产版本可定位到决定、实验 manifest、证据和批准记录 |
| 可回滚 | 已晋级变更具备明确前一版本与恢复步骤；演练可恢复到前一批准状态 |
| 抗越权 | 没有匹配 Charter 授权和批准事件的写操作被策略层拒绝并留痕 |
| 可移植 | 项目适配器不绑定某一模型、框架或厂商；核心事件模式可导出 |
| 人类可用性 | 高风险决策显示替代方案、反方证据、影响与回滚；禁止只有“批准”按钮 |

## 明确非目标

v0.2 不承诺通用人工智能、自行修改基础模型、无人类监管的生产自治，或把用户一句临时偏好自动升级为全局政策。
