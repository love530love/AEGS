# 演进审议记录：可信接管与证据优先

- 日期：2026-11-15
- 状态：已审议，待进入 P0 实施
- 范围：AEGS 当前控制平面原型

## 审议输入与边界

本次获得两份独立的角色化只读审查：治理/安全/人因审查，以及模拟项目负责人、开发者与新接手 Agent 的采用审查。它们不是现实世界专家认证，也不代表真实用户调研。第三份架构审查未返回可用意见，因此不计入共识。

共同事实：当前 5 项测试通过；`aegs verify` 能校验现有 JSONL 哈希链，但不能证明事件、审批身份或治理文件未被有能力的本地写入者整体重写。

## 结论

AEGS 适合作为 **单机、低风险项目的可解释原型**，尚不适合作为真实审批、敏感项目治理或生产权限控制面。

审议决定：暂停能力雷达、自动外部检索、全局经验库和多 Agent 编排；下一里程碑命名为 **可信决策与可验证接管**。

## P0：必须先完成

| 编号 | 能力 | 验收门槛 |
|---|---|---|
| P0-1 | `aegs takeover` 过期门控 | 比较当前 Git/架构快照/账本/交接包；任一不一致返回 `STALE` 或 `HOLD`，并禁止自动行动 |
| P0-2 | 交接证据绑定 | Handoff 包含 Git tree 或代码版本、账本头哈希、架构快照内容哈希、生成时间、有效性与证据引用 |
| P0-3 | 结构化提案与决策 | YELLOW/RED 必须有范围、替代方案、影响、反方证据、评估标准、有效回滚工件和决定理由 |
| P0-4 | 事件一致性 | 单写入者/文件锁或事务存储；并发写入不得导致分叉链或丢失事件 |
| P0-5 | 拒绝旁路写入 | `state`、提案和指令均可由账本重放或具有内容绑定；直接编辑触发 `HOLD` |

## P1：真实使用前完成

- 认证主体到角色的映射，禁止网页字段自报 Owner。
- 审批/账本锚定到签名 Git tag、受保护远端或独立不可变存储。
- 敏感信息使用 allowlist、可配置忽略、扫描与脱敏，而非只靠文件名和后缀。
- Directive 实现真正的到期时间、权限范围、事实更正的证据/冲突队列。
- `HOLD` 成为所有未来执行适配器可执行的全局熔断。

## 延后项目

多 Agent 辩论、自动技能安装、联网能力雷达、跨项目全局记忆和生产部署，均在 P0/P1 验收后再评估。协议互通不等于授权、可信身份或安全执行。

## 仍存分歧与开放项

- 单机个人项目应使用签名 Git 锚点还是独立 WORM 存储？前者摩擦低，后者独立性更强。
- 事件日志应继续使用 JSONL+锁，还是尽早转 SQLite 事务日志？需用并发、恢复和可移植性基准决定。
- `takeover` 的 STALE 状态在何种项目可以由 Owner 覆盖，何种项目必须强制重新发现？
