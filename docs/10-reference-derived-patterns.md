# 来自 3D 项目的可迁移架构模式

本文件将 `F:\PythonProjects1\3D\docs` 的已验证工程治理模式抽象到 AEGS。仅迁移通用控制机制；不迁移福利彩票的随机性结论、数据源、预测口径或任何领域特定阈值。

| 3D 项目模式 | AEGS 对应设计 | 收益 |
|---|---|---|
| 原始数据、验证、清洗、特征、模型、回测分层且上游只读 | Raw Trace、Validate、Experience、Capabilities、Experiments、Evaluation、Versions 分层 | 防止候选能力篡改事实或越层依赖 |
| SQLite 权威库 + 追加 JSONL 审计账本 + 快照 | 权威状态库 + Event Ledger + 哈希化 Trace/环境快照 | 可恢复、可重放、可审计 |
| 预测先冻结，后取得实际结果 | 提案先冻结基线、任务集、指标和阈值，后运行候选 | 防止结果导向的标准漂移 |
| 简单基线长期保留，复杂模型必须同表比较 | 基线能力包长期保留，候选必须证明相对改善且无回归 | 避免“新即更好”的错觉 |
| 模型提案、五类专家意见、投票、回滚 | Evolution Proposal、独立审查、政策门控、Promotion/Reject/Rollback | 将进化从建议变成可追责决策 |
| 数据/日志异常即停更，恢复后再继续 | 证据链断裂、权限越界、快照缺失即 `HOLD` | 不在不可信状态下继续自我进化 |
| 导出可重建，原始事实不静默改写 | 报告和图谱为派生产物，不能覆盖 Trace、Ledger 或批准版本 | 防止“漂亮报告”替代事实 |

## AEGS v0.1 采用的强制控制

1. 任何 GREEN/YELLOW 提案都使用统一模板并生成不可变 `proposal_id`。
2. 每次 Shadow Lab 运行都输出 manifest：代码/策略版本、输入与 Trace 哈希、模型与工具版本、参数、随机种子、时间窗和环境指纹。
3. Promotion 前必须保留基线、候选、指标、反例、独立审查与回滚指针。
4. Event Ledger 或关键快照校验异常时，自动 Promotion 禁止，进入 `HOLD`；恢复操作本身也必须留痕。
5. 高风险治理变更沿用更严格的 RED 审查，不得由提案者单独批准。

这些模式将使 AEGS 从概念性“演化循环”落实为可执行的证据与发布纪律。
