# 经验、证据与溯源

## 三个层次

- **Trace/Event（事实）**：某次输入、调用、观察、决策和结果实际发生了什么。
- **Evidence（可核验主张）**：由 Trace、外部来源或实验产生，并保留来源、时间、适用范围与可信度。
- **Experience（结构化归纳）**：从多个事实和证据导出的可复用模式、失败教训或候选能力。

经验不是事实，未经验证的经验也不能直接改变生产系统。

## 最小溯源链

`Requirement -> Trace -> Observation -> Hypothesis -> Experiment -> Evidence -> Decision -> Version`

任一 Decision 必须列出支持与反对证据、责任角色、置信度、适用范围、批准记录及被替代关系。系统应能回答“为什么当前版本如此”，也能重放到特定历史版本。

## 持久化与恢复原则

- **权威状态**：事务型数据库保存当前已批准版本、实体关系和状态机；不以导出文件作为唯一事实来源。
- **审计账本**：追加式 Event/JSONL（可选前序哈希链）保存提交、拒绝、回滚和异常事件；历史行不可编辑。
- **原始快照**：外部工具响应、配置和关键输入按内容哈希归档，以支持离线重放与来源变更审计。
- **便利导出**：报告、图谱视图和索引可以重建，不可反向覆盖权威状态或账本。

失败提交必须原子回滚当前事务，并追加失败事件；账本完整性异常时停止自动演进，不得继续写入以掩盖证据断裂。
