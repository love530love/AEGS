# 已采纳架构决策

| ID | 决策 | 理由 |
|---|---|---|
| D-001 | AEGS 独立于 Prompt 项目 | 架构目标超出提示词工程 |
| D-002 | Prompt 是 Cognitive Engine 的策略 | 避免将能力与单一载体绑定 |
| D-003 | Experience System 为一等公民 | 记录任务、行动、结果、失败与因果 |
| D-004 | Trace 为事实和证据基础设施 | 所有反思、评估、升级均须可引用 |
| D-005 | Skill 为版本化能力单位 | 使经验可执行、验证和复用 |
| D-006 | 专家采用动态治理角色 | 按复杂度和风险最小化组建 Council |
| D-007 | 设置 User Council 与独立 Red Team | 防止“技术正确”替代真实需求或风险审查 |
| D-008 | 引入 Capability Gap Detection | 以证据提出新技能/角色，而非随意扩张 |
| D-009 | Evolution 必经提案、实验、评估、晋级 | 使改变可控、可审计、可回滚 |
| D-010 | v0.1 不修改基础模型 | 首先验证运行时能力进化的治理闭环 |
| D-011 | 宪法与治理边界高于进化机制 | 防止系统以“升级”为名绕过约束 |
| D-012 | Reject 不等于 Delete | 保留失败版本、反例和经验，避免重复犯错 |
